0.0.428 (S3 FIX: Page theme parity for extension panels in a dark app)
- Why: video 2: the injected "Export to PDF" card was WHITE with invisible text, in Quetta it is dark. Thazir darkens a light page itself, but the page still says prefers-color-scheme = light, so a site that themes itself (ChatGPT "System") stays light and its extension reads "light" once at start.
- How: new ExtTheme.kt + assets/shim/theme-hint.js. At document start, in the page world, ONLY on the origins of installed extensions' content scripts, matchMedia('(prefers-color-scheme: dark)') answers true (light query false) when the app is dark AND Thazir shows this page dark (Dark pages ON, or the site rule is Dark; a site rule Original = no change). So the site switches to its real dark theme and sets html.dark. Also (app dark only): run_at document_idle waits for the page "load" event or 1.5 s, whichever is first (Chrome idle meaning); document_end stays on DOMContentLoaded.
- Switch: Settings > Extensions > "Match page theme": Auto (default) > On (always when the app is dark, ignores Dark pages) > Off (0.0.425 behaviour). Reset: key ext_theme is in the Settings "general" Reset list. Report center "Extension compat" shows the choice.
- Changed files: ExtTheme.kt (new), assets/shim/theme-hint.js (new), ContentInjector.kt (wrap idle param, cache signature, theme hint added first in addExtScripts), TabManager.kt (applyDarkPages refreshes scripts), SettingsScreen.kt (row + RESET), DiagMore.kt, ExtProbe.kt (1 line), HowToUse.kt, app/build.gradle.kts.
- CHANGED BEHAVIOUR: light app = nothing changes. Dark app + extension with content scripts: pages shown dark by Thazir report dark to the page's JS (only matchMedia JS answers, CSS @media is not changed). Idle content scripts of installed extensions may start up to 1.5 s later than before on slow pages (dark app only). Built-in Media Grabber and pages without extension origins: untouched.
- COULD BREAK: a site that is already dark by itself and an extension that expects light (use Match page theme Off). The social own dark rule (SocialDark) is not read by the hint. No fix yet for the exporter dialog if its text colour is wrong for another reason: S1 report (Extension compat) shows the real numbers.
- NOT tested: Gradle build (CI), device. node test of the hint script passed (Dark pages ON / OFF, site rule Dark / Original, On, other site).
- DEVICE TEST: 1) Dark app, Dark pages ON, open chatgpt.com, reload, open the ChatGPT Exporter dialog (Export to PDF) and "Select Messages": dark card, labels readable. 2) Settings > Extensions > Match page theme = Off, reload chatgpt.com: old white look returns (proves the switch). 3) On, Dark pages OFF: dark. 4) Light app: no change in any page. 5) Open Report center on chatgpt.com: "Extension compat" shows "prefers-dark" and html class; send it if the card is still white. 6) YouTube / other sites with no extension behave as before.
- Rollback: delete ExtTheme.kt and theme-hint.js and revert the hook lines (ContentInjector: wrap idle, sig, theme hint block, extEntries sync; TabManager 1 line; SettingsScreen row + RESET; DiagMore; ExtProbe; HowToUse).
