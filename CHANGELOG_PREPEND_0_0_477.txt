0.0.477 (FIX: extension background workers and script refresh no longer start / stop while a page is loading; crash breadcrumbs for extension workers)
- Base = 0.0.476. Changed files: app/build.gradle.kts, ExtBackground.kt, ExtApi.kt, ContentInjector.kt, TabManager.kt. No new file, resource, permission or dependency.
- WHY: the native WebView crashes (SIGSEGV, null pointer, libwebviewchromium, main thread, 3 s after a page start; last one on m.youtube.com) began to be reported after the extension updates (0.0.431 added webNavigation events at every page start). Code check: every page start (TabManager.onPageStarted -> ExtApi3.started -> ExtApi.emitExt with wake) and every webRequest / tabs event could start a STOPPED extension worker = a whole hidden WebView (new WebView, bridge, loadUrl) exactly while Chromium starts the page; an idle worker (45 s) was destroyed at any time, also in the middle of a page load. Same pattern as the pop-up WebView churn of 0.0.468. NOT proven (the native frames have no symbols); this removes the most likely overlap and records what happens.
- 1. ExtBackground: new pageTouch() (TabManager calls it at onPageStarted and onPageFinished of a normal tab) and calm() (= no page start / finish in the last 3 s).
- 2. ExtApi.emitExt: for events that start with webNavigation. / webRequest. / tabs. a stopped worker is started through the new ExtBackground.ensureCalm(): it waits until calm() (checked every 1 s, max 12 s), then ensure() as before and the event is delivered. While waiting, one extension keeps at most 20 queued events, more are dropped (a burst of webRequest events). Clicks (action.onClicked), alarms, context menus, commands and runtime messages still start the worker AT ONCE.
- 3. ExtBackground idle stop (45 s): only when calm().
- 4. ContentInjector.refresh (extension installed / updated / switched, Dark mode, Match page theme, private allow): if a page loaded in the last 3 s, the whole refresh is queued once (2.5 s later, many calls = one run), because removing / adding document-start scripts on a loading WebView is risky.
- 5. Breadcrumbs (Report center > Last events, and the native crash report): "extbg: worker start <name>", "extbg: worker start deferred <name>", "extbg: worker stop (<why>) <name>" (name masked, 24 chars). CrashGuard state line now has "bgWorkers=<n>".
- COULD BREAK: (1) an extension that does its work in the service worker at page start (webNavigation / tabs) acts up to ~3 s later than before, the first events may be dropped on a burst of more than 20; a page that needs that extension in the first second may look unchanged until it runs. Content scripts are not affected. (2) Extension install / update changes reach open tabs 2.5 s later while a page is loading. (3) With a page loading all the time (many tabs finishing), an idle worker stays a little longer.
- NOT tested: Gradle build (CI), device. Written without a Kotlin compiler; brackets counted (balanced). If CI shows an error, it is in ExtBackground.kt near "0.0.477" (ensureCalm / waitCalm).
- DEVICE TEST: (1) install / enable an extension with a service worker and webNavigation, open a site: Diag shows "worker start deferred" then "worker start" about 3 s after the page; the extension still works. (2) tap the extension button / alarm: worker starts at once (no "deferred"). (3) Extension update or switch while a page loads: scripts reach the tab a moment later, no crash. (4) Leave the app idle: worker stops after about 45 s ("worker stop (idle)"). (5) After a native crash the report's "Last events" shows the extbg lines before it; CrashGuard line has bgWorkers.
- NEXT if it still crashes: send the report. If "extbg: worker start" is right before the crash, make the worker start only on a tap / message (remove the passive wake completely) or turn off the extension that owns it; if there is no extbg line, the extension workers are cleared and the next suspects are the document-start scripts / WebMessageListener "*" (ContentInjector.attach) or the page itself.
- ROLLBACK: restore ExtBackground.kt, ExtApi.kt, ContentInjector.kt, TabManager.kt and app/build.gradle.kts from 0.0.476.
