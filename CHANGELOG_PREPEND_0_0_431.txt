0.0.431 (S6 BUILD: webNavigation events, runtime.reload, search.query, browsingData, storage quotas)
- Why: installed extensions had only a fake webNavigation (built from tab updates, no history / error events), no search.query, no browsingData, a no-op runtime.reload.
- How: new ExtApi3.kt (handlers "ext.<api>": installed extensions only, the built-in Media Grabber is untouched). (1) webNavigation, main frame only: TabManager hooks (onPageStarted, onPageFinished, doUpdateVisitedHistory, onReceivedError) call ExtApi3 which sends onBeforeNavigate + onCommitted, onDOMContentLoaded + onCompleted, onHistoryStateUpdated / onReferenceFragmentUpdated (in-page changes), onErrorOccurred. Only to extensions that have the "webNavigation" permission (others get nothing and no worker wake); stopped workers wake through the normal ExtApi.emitExt path. Private tabs, Home, extension pages and non-http pages send nothing. addListener(fn, {url:[...]}) filters (host / path / query / url Equals Contains Prefix Suffix, schemes, ports, urlMatches, originAndPathMatches) are applied in the shim. getFrame / getAllFrames answer for the main frame (frameId 0) only. (2) runtime.reload restarts the extension's worker. (3) search.query opens the default search engine in the current tab (default), the tab with tabId, or a new tab (NEW_TAB / NEW_WINDOW); needs the "search" permission; never navigates a private / Home / extension tab (a new tab is opened instead). (4) browsingData.remove / removeHistory / removeCache / removeCookies / removeDownloads / removeLocalStorage / removeIndexedDB / removeServiceWorkers / removeFileSystems / removeWebSQL / settings (permission "browsingData"): always shows a confirm box naming the extension and what will be deleted; Delete runs the same code as Settings > Delete browsing data (ClearData.apply), Cancel answers "The user denied this request.". history follows "since"; cookies / site data / cache are always all-time (Android limit, the box says so). Single-site deletion (origins) and passwords are refused with a clear error; formData / appcache / pluginData do nothing. (5) storage.sync / storage.local quota constants (QUOTA_BYTES, MAX_ITEMS ...) exist like in Chrome.
- Changed files: ExtApi3.kt (new), ClearData.kt (1 line: apply), ExtApi.kt (register line, allow-list rows, permission rows), TabManager.kt (4 hook lines), assets/shim/chrome-shim.js, HowToUse.kt, app/build.gradle.kts.
- CHANGED BEHAVIOUR: installed extensions with the webNavigation permission now get real events (before: events built from tab updates, no history / error events). An installed extension WITHOUT the permission that used webNavigation events before gets no events now (Chrome behaves the same). Built-in Media Grabber: unchanged (node check: identical members, old webNavigation kept).
- COULD BREAK: a stopped worker of an extension with webNavigation listeners now wakes on every page load of a normal tab (more battery; the report shows it). Event order: onCommitted is sent right after onBeforeNavigate (Thazir has no separate commit signal). Sub frames never send events (documented limit). runtime.getBackgroundPage (MV2) stays "not supported" (a WebView cannot hand out another WebView's window). Per-item sync quota (8 KB) is a constant only, not enforced.
- NOT tested: Gradle build (CI), device. node tests of the shim passed (filters, has / remove listener, bridge calls, built-in unchanged). Kotlin only checked for brace / paren balance.
- DEVICE TEST (needed only): 1) Extension that uses webNavigation (for example one that reacts to page load): open a normal https site: it reacts once per page, also after a link tap and after a page with in-page navigation (YouTube / Google). No reaction in a private tab. 2) Extension with a "clear data" feature, or the Report center after use: a confirm box appears with the extension name; Cancel = nothing deleted; Delete = deleted. 3) Extension with a search action: the default search opens. 4) Media Grabber (built-in): popup, queue, a download = same as before. 5) Report center > Extension API gaps: send the text.
- Rollback: delete ExtApi3.kt, ClearData.apply, the ExtApi3.register() line and the new regex / NEEDS rows in ExtApi.kt, the 4 ExtApi3 lines in TabManager.kt, the second "if (GAPS)" block (S6) and the "if (GAPS) return;" line in the WN loop of chrome-shim.js, the HowToUse line.
