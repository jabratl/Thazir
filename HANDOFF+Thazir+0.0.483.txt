DONE (1): PrivateTabs.keepOn / setKeep (pref priv_keep in mgb_ui, default ON; Settings > Privacy and security > Incognito > "Keep Incognito tabs", also in the reset list). TabManager.saveSession writes the Incognito tabs into their OWN keys ptabs (addresses) / pts (last opened) in prefs mgb_session, only while keepOn; the normal list (tabs / ts / tp / pn / groups / active) is untouched and still never holds a private tab. TabManager.restoreSession first calls the new restorePrivate(sp): makes each saved address as a lazy Incognito tab (pending = url, NOT selected, no group); the flag restoringPriv stops newTab from calling purgePrivate() for the first one. If nothing was restored (switch OFF or the list is empty) the Incognito profile is wiped like in 0.0.478 (purgePrivate). A normal tab is still the one that is shown after start (restoreSession returns false when only Incognito tabs were saved = caller opens a fresh Home tab). close(): after an Incognito tab is closed saveSession() runs at once, so a killed app never brings back a tab (or a list) the person closed; closing the last Incognito tab still wipes the profile (cookies / logins), "Close all Incognito tabs" (Settings, notification) = the way to end it. DONE (2): the cause was the cookie store. Incognito tabs use the WebView profile TabManager.PRIVATE_PROFILE; Downloader (OkHttp) and DownloadsApi.startPlain read only CookieManager.getInstance() (normal profile). Now DlItem.priv (saved in the store as priv) -> Downloader.cookieManagerOf(priv) (ProfileStore.getProfile(PRIVATE_PROFILE).cookieManager; null = no profile = no cookies, the normal store is never used for an Incognito item; WebView without MULTI_PROFILE = normal store like the tabs) -> two cookie jars (class WebJar) and a second client privClient (client.newBuilder(), same pool) chosen in Downloader.open(). priv is set in startPlain (DownloadsApi.isPrivWeb(src): the WebView belongs to a private tab; link / blob / image downloads of a tab and the Ask-before-download sheet) and in chrome.downloads.download (DownloadsApi.fromPrivate: the calling page / its opener is a private tab, else the Referer header is the address of a private tab and of no normal tab, else the tab on screen is private). An Incognito startPlain item gets NO saved Cookie header (it would be written to the downloads list); the jar adds the cookies per request. Blob downloads already ran inside the page WebView (right profile).
