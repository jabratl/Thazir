0.0.429 (S4 BUILD: chrome.* safety net + gap log)
- Why: an extension that touches a chrome.* name Thazir does not have used to stop (undefined is not a function). We also did not know which missing calls matter.
- How: (1) chrome-shim.js: for INSTALLED extensions only (flag "gaps" in their config) the missing names of Chrome's API are added where the name is still empty: tabGroups, browsingData, search, clipboard, tts, power, privacy.*, proxy, readingList, userScripts, debugger, gcm, system.cpu / memory / storage / display, plus missing members of downloads, notifications, permissions, scripting, runtime. A method rejects (or sets runtime.lastError in callback style) with "Not supported in Thazir: <api>", never fake data; an event object never fires; constants are filled. Real handlers and the older stubs always win. (2) every such call, every "Not supported in MGB" (ExtApi.gate) and every "Not implemented" (ChromeBridge) is counted by ExtGaps.kt: only the api name, per extension, max 200 rows, own prefs file mgb_ext_gaps (not in Backup, not in Reset). (3) Report center: new section "Extension API gaps" (extensions still installed) + 1 verdict line "ext-gaps".
- Changed files: ExtGaps.kt (new), assets/shim/chrome-shim.js, ChromeBridge.kt (2 hook lines), ExtApi.kt (2 hook lines), ContentInjector.kt (1 flag), DiagReport.kt, DiagRules.kt, HowToUse.kt, app/build.gradle.kts.
- CHANGED BEHAVIOUR: extension pages / workers of installed extensions now have more (empty or failing) chrome.* names; a feature check like "if (chrome.tabGroups)" is now true and the call then fails with the message above. Built-in Media Grabber and content-script frames: unchanged (node check: identical member lists without the flag).
- COULD BREAK: an extension that crashed before at load and now runs on may show a feature that does nothing. Shim grew about 4.5 KB.
- NOT tested: Gradle build (CI), device. node tests of the shim passed (promise + callback style, throttle 1 per 5 s, real members kept, built-in and content kinds unchanged).
