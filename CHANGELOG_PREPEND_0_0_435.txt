0.0.435 (S10 BUILD: CSS compat B - colours, units, inset, switch, report)
- Why: finish the old-WebView fallback of 0.0.434. Modern colour syntax (Tailwind v4 uses oklch + color-mix) and some units are not understood by an old Android System WebView, so extension panels lose their colours / sizes.
- How: css-compat.js (same script as S9, still added ONLY when needed) now also converts, in declarations only: color-mix(in srgb | oklab, a p%, b), oklch(), oklab(), lab(), lch(), hwb() with literal colours -> rgb() / rgba(); dvh / svh / lvh (and w / i / b / min / max variants) -> vh / vw / vmin / vmax; "inset: a [b [c [d]]]" -> top / right / bottom / left. color-mix with var() / currentcolor stays as it is; if its first colour is literal a static fallback colour is written just before it. "@supports (color: color-mix(...))" blocks are NOT touched, so the old engine gives them the same "false" it would give anyway and the fallback declaration wins. Relative colour syntax (from ...) is left alone. Cheap counters (rewrites + ms, no content) live in window.__mgbCssStats.
- UI: Settings > Extensions > "CSS compatibility" row (Auto > On > Off, summary hint shows the WebView version, reload the page after changing). Reset on that card clears it (key ext_css was added to RESET in S9). Report center: section "Extension compat" has a line "CSS compat: active (WebView is old) | not needed | on | off" and, when the current tab ran the rewriter, "CSS compat on this page: N rewrites, M ms". New advice rule ext-css-off (WebView below 120 and switch Off). Settings > "Changed from default" already lists the switch (S9).
- Changed files: app/build.gradle.kts, app/src/main/java/com/jabra/mgb/{ExtCssCompat.kt, ExtProbe.kt, SettingsScreen.kt, DiagRules.kt, DiagReport.kt, HowToUse.kt}, app/src/main/assets/shim/css-compat.js, CHANGELOG_PREPEND_0_0_435.txt, HANDOFF_Thazir_EXT_PLAN_0.0.435.txt
- CHANGED BEHAVIOUR: on a WebView below 120 (or switch On): colours / units / inset in extension CSS are rewritten. Modern WebView + Auto: nothing added, same as 0.0.434. New Settings row and 1 report line.
- COULD BREAK: gamut-limited colours are clamped to sRGB (oklch values outside sRGB look slightly different from Chrome); color-mix only for srgb and oklab spaces (other spaces left unchanged); "inset" with var() parts is split by spaces only (a single var() holding several values is left as 4 equal sides).
