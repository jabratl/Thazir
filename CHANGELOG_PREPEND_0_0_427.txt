0.0.427 (S2 FIX: Extension popup / options / extension tabs fit the phone)
- Why: video 2: the popup of "ChatGPT Exporter" was a whole desktop page (about 40 % scale) in the top-left of the 480 dp window. The popup has no viewport meta, and Thazir laid it out at about 980 px.
- How: new ExtFit.kt. A document-start script (only https://appassets.androidplatform.net/ext/<id>/... of an INSTALLED extension) adds a viewport meta at the phone width. After the page loads it is measured up to 3 times in 1.5 s; if the content is wider than the window (fixed desktop popup) the viewport becomes the measured width (max 900), so the page is scaled once. That width is kept per extension version + page (pref ext_fit_w), so the next open has no jump. A page with its own viewport meta is never changed. Popup window height now wraps the content (40 % to 80 % of the screen, never under 240 dp).
- Same logic for an installed extension page opened as a tab (script added in ContentInjector.addExtScripts, measuring from TabManager.onPageFinished).
- UI: Settings > Extensions > tap an extension > "Page width": Auto > Phone width > Desktop width (Desktop = old behaviour). Reset: keys ext_fit, ext_fit_w are in the Settings "general" Reset list; removed with the extension.
- Changed files: ExtFit.kt (new), ExtScreen.kt, TabManager.kt (1 line), ContentInjector.kt (1 hook), ExtListScreen.kt, SettingsScreen.kt (RESET), DiagMore.kt, HowToUse.kt, app/build.gradle.kts.
- CHANGED BEHAVIOUR: popups / options pages of installed extensions are laid out at phone width (before: 980 px for the popup). Built-in Media Grabber pages untouched (script only matches 32-letter a-p ids of installed extensions; ExtFit ignores everything else). If the document-start script is not supported the popup keeps the old wide page.
- COULD BREAK: a popup that is wider than the window and has its own tuned CSS (use Desktop width for it); popup that fills with content after 1.5 s may stay smaller than needed (it scrolls; min height 40 %).
- NOT tested: Gradle build (CI), device. Dynamic viewport change after load is assumed to relayout (Chrome WebView does).
- DEVICE TEST: 1) Settings > Extensions > ChatGPT Exporter, Page width = Auto. Open its popup from the menu: it must fill the width with readable text, window as high as its content. 2) Close and open it again: no jump in size. 3) Tap Page width to Desktop, reopen: old tiny look (proves the switch). 4) Phone width: full width. 5) Rotate the phone with popup open, then reopen. 6) Open the extension Options (extension tab and window): readable, no tiny page. 7) Media Grabber popup, Queue, Manga, History look exactly as before. 8) Settings > General > Reset to default: Page width choices go back to Auto.
