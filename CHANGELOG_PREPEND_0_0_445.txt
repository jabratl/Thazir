- WHY: Diagnose report 2026-11-15 (Xiaomi 2412DPC0AI, Android 16, WebView 156.0.8078.47, app 0.0.444): "App exits" shows CRASH_NATIVE (signal 11, was foreground, process main) twice in 24 h (11-14 18:25:36 and 11-15 00:26:19), and the owner says an extension was running. The report had no stack, so the place of the crash was unknown. The StackOverflowError shown under "Last crash" in that report is from 0.0.410 (already fixed in 0.0.413), not a new crash.
- 1) NEW in the report, section "App exits": a block "Native crash stack (newest main process crash, <time>)". DiagExtra.nativeCrashLines reads ApplicationExitInfo.traceInputStream of the newest CRASH_NATIVE of the MAIN process (max 2 MB). Android 12+ = protobuf tombstone: a small built-in protobuf reader (pbFields / tombstoneLines) prints the signal + code name (field 10), abort message (14), causes (15) and the frames of the crashing thread (thread whose id = tid, field 6 / 16 / 4: lib file name + relative pc + function name when the library has symbols). Older = text tombstone: textTombstoneLines keeps the signal, "Abort message", "pid:" and "#NN pc" lines. Result max 70 lines, each cut to 200 chars and passed through Diag.mask. Nothing readable = one line ("Android kept no stack for this crash" / "stack could not be read (N bytes, format not recognised)"). Every part is in try / catch: the report can not crash because of it.
- Read only. No setting, key, permission, network call or stored value changed. The field numbers come from AOSP tombstone.proto (Tombstone: tid 6, signal_info 10, abort_message 14, causes 15, threads 16; Thread: id 1, name 2, current_backtrace 4; BacktraceFrame: rel_pc 1, function_name 4, file_name 5). If a future Android changes them the text fallback / "format not recognised" line shows it.
