0.0.446 (FIX: stutter when switching Bookmarks / History / Downloads)
- WHY: owner report: switching between the three pages freezes the UI for a moment (a few ms to tens of ms), not smooth; Quetta does not. CAUSE (code read, not profiled): (a) BookmarksScreen.favTile called Favicons.get(host) for EVERY row on the UI thread; get() = BitmapFactory.decodeFile from disk when the icon is not in the 80 entry memory cache, so a History page of up to 300 rows did up to 300 disk reads + decodes before the slide even started. (b) switchMode / open built ALL rows (History up to 300, Bookmarks and Downloads unlimited, each Downloads saved file row has 2 MaterialButtons) in one go on the UI thread, before the animation start. (c) the Bookmarks <> Downloads hand over builds a whole new Dialog, so (a) and (b) hit the first frame of the slide.
- 1) Favicons.kt: NEW peek(host) = memory cache only (no disk) and NEW lookup(host, done) = decode of the saved icon on one worker thread (decodePool), then done(bitmap) on the main thread; no saved icon = fetch() as before. get() and fetch() are unchanged.
- 2) BookmarksScreen.favTile: Favicons.peek(host) first (shows the icon at once when cached), else the letter tile and Favicons.lookup (icon appears a moment later). No disk read on the UI thread any more.
- 3) NEW BookmarksScreen.fillChunked(box, jobs, alive): the rows are first collected as small lambdas, the first 10 are added at once, the rest 8 per frame (box.post). BookmarksScreen.render() and DownloadsScreen.render() use it ONLY when the list is empty (new page / mode switch / filter change / first open); a refresh of a filled list (select, sort, folder change, download progress every second) stays synchronous, so the scroll position is kept. A newer render() stops the older batches (renderGen). `visible` (select all) is still filled completely at once.
- Nothing else changed: same rows, same order, same texts, same keys, no setting, no new permission, no new dependency. Visible difference: a row icon of a host that is not in the memory cache shows the letter tile for a moment, then the icon.
- NOT tested: Gradle build (CI), device. The cause is from reading the code; no profiler run.
- DEVICE TEST: 1) Bookmarks > History > Downloads > Bookmarks, 10 times quickly: the slide and the pill stay smooth, no hitch at the start. 2) History with a long list: scroll to the bottom at once after opening: all rows are there (the rest arrives within a few frames). 3) Select mode in History at row 100 + tap rows: the scroll position stays, check marks work, Select all counts every row. 4) Type in the search box: list filters. 5) Downloads with a running download: progress moves, scroll position stays. 6) Icons: first open shows letters then icons; second open shows icons at once.
- Rollback: Favicons.kt remove peek / decodePool / lookup; BookmarksScreen: favTile back to Favicons.get + fetch, render() back to box.addView per row (remove fillChunked + renderGen); DownloadsScreen: render() back to box.addView per row (remove jobs / renderGen).
