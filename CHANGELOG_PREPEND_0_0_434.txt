0.0.434 (S9 BUILD: CSS compat for an OLD WebView - nesting, @layer, @property)
- Why: an extension built with modern CSS (Tailwind v4 style) breaks on a phone whose Android System WebView is old (no CSS nesting before 120, no @layer before 99, no @property before 85): panels lose their layout. Your video phone is NOT affected (its WebView is new); this protects other phones.
- How: new assets/shim/css-compat.js + ExtCssCompat.kt. When needed, a small script is added at document start and rewrites the style text that scripts add (style.textContent / innerText, appendChild / append of <style>, innerHTML with <style>, CSSStyleSheet.replaceSync / replace / insertRule, shadow roots included): (1) CSS nesting -> flat rules (declaration order kept), (2) @layer -> removed, rules stay in source order, (3) @property -> its initial-value written as a normal declaration. Any error = the original CSS is used (fail-open). Result cache: max 64 entries / 2 MB.
- When it runs: Auto (default) = Android System WebView version below 120 (or the Report center probe says nesting / @layer / @property is missing). Pref ext_css (absent Auto, 1 Off, 2 On) exists but has NO Settings row yet (S10 adds it). On a modern WebView nothing is added anywhere (same as 0.0.433).
- Where added: tab pages that match an installed extension's content scripts (before those scripts), extension pages opened as tabs, and the popup / options window of an installed extension. Built-in Media Grabber pages: untouched.
- Changed files: app/build.gradle.kts, app/src/main/java/com/jabra/mgb/{ExtCssCompat.kt (new), ContentInjector.kt (2 hook lines), ExtScreen.kt (1 hook line), SettingsScreen.kt (RESET key), DiagMore.kt (changed list), HowToUse.kt}, app/src/main/assets/shim/css-compat.js (new), CHANGELOG_PREPEND_0_0_434.txt, HANDOFF_Thazir_EXT_PLAN_0.0.434.txt
- CHANGED BEHAVIOUR: only on a WebView older than 120: extension CSS is rewritten as above. Nothing else.
- COULD BREAK: @layer flattening changes priority between layered and unlayered rules of the SAME sheet set (known limit). Page-own styles added by page JS go through the same hook on an old WebView (they could not use nesting / @layer there anyway). Colours (color-mix, oklch), dvh, inset are NOT converted yet (S10).
- NOT tested: Gradle build (CI), device. node tests passed on _fixture/tailwind-v4-sample.css (50 KB): braces balanced (in 614/614, out 513/513), 0 "@layer" / "@property" left, only escaped class names contain "&", 56 ms, idempotent, cached run 0 ms; unit cases: nested rule, "&" in :where(), nested @media, @layer statement + block, @property, selector lists, braces in custom property, broken CSS = unchanged. Kotlin only checked for brace / paren balance.

  2) Only if you have an old phone (WebView below 120): open any extension panel; it must keep its layout. (Skip if you have none.)
