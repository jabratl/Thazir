ROOT CAUSE ANALYSIS (code read + grep; NOT device tested):
- E1 (CONFIRMED by code): ExtScreen.kt (about line 180) sets useWideViewPort = true + loadWithOverviewMode = true for a popup page; popup.html of the extension has NO <meta viewport> (checked, _fixture/chatgpt-exporter/popup.html). WebView therefore lays the page out at about 980 CSS px and shrinks it to the 480dp window. Quetta (Chrome) treats an extension popup at device width. TabManager.kt (lines 177, 236, 303, 349, 567, 974) sets the same wide viewport for every tab, so an extension page opened in a TAB (options page) has the same problem.
- E2 / E3 (MOST LIKELY, not proven): the extension reads the page theme ONCE at start: Pv = document.documentElement.classList.contains("dark") || dataset.theme === "dark" (content.js). Pv true -> its shadow-DOM wrapper gets class "dark" (dark tokens), false -> light tokens (white card). In Quetta chatgpt.com gets html.dark (real prefers-color-scheme). In Thazir the page looks dark but html has no "dark" class when the script runs (candidates: (a) Thazir dark pages = WebView algorithmic darkening of a LIGHT page while prefers-color-scheme says light, so the site never self-themes; (b) document_end timing: Thazir runs it on DOMContentLoaded, ChatGPT sets the class later; (c) per-site rule SiteDark / "Dark pages" OFF). The invisible labels = host page text colour (white) inherited into the shadow root over a light card. S1 measures it, S3 fixes it.
- Hypothesis "old WebView lacks CSS features" is UNLIKELY: the extension CSS (Tailwind v4.2.2) uses native CSS nesting, @layer, @property, color-mix; the checked checkboxes (rule &[data-state=checked]) render purple in Thazir, so nesting works. Still planned as a SAFE FALLBACK for other users / other phones (S9, S10), only active when the WebView is old.

2. PROJECT SUMMARY
================================================================================
Thazir (package com.jabra.mgb, internal name MGB) = Android browser app, Kotlin, minSdk 24, targetSdk 34, XML layouts + programmatic Views (no Compose), Material 3, androidx.webkit 1.11.0, media3 1.3.1. Built only by GitHub Actions (.github/workflows/build.yml, "Build APK" v3.1, applies patch zips from the repo in version order, signs, releases, in-app updater). NO Android SDK / Gradle in the work space: only syntax checks are possible. 155 files in repo root (many HANDOFF / CHANGELOG files), 571 files total. Latest version 0.0.425 (optional "Ask before download" sheet).
Extension subsystem (what this plan changes) = a WebView based emulation of Chrome MV3 extensions:
 - content scripts of installed extensions run in the PAGE's main JS world inside one private function scope that receives a `chrome` shim object (ContentInjector.kt, assets/shim/chrome-shim.js); injected with WebViewCompat.addDocumentStartJavaScript(web, script, originRules).
 - every chrome.* call from a shim goes over WebMessageListener "MGBBridge" as JSON {t: token, i: callId, a: "api.name", p: [args], x: extId} to ChromeBridge.kt (token per extension = ContentInjector.tokenFor(id) = SHA-256(token + ":" + id)).
 - background = one hidden WebView per extension (ExtBackground.kt; MV3 service worker is emulated as a page), offscreen documents in OffscreenHost.kt, popups / options / extension tabs = pages served from https://appassets.androidplatform.net/ext/<id>/... (ContentInjector.EXT_ORIGIN / EXT_BASE), shown in ExtScreen.kt (Dialog) or in a normal tab.
 - 2 kinds of extensions: (1) built-in "Media Grabber" engine V82 (ContentInjector.EXT_ID = "mgbextensionidmgbextensionid0", assets/ext/*, EngineHost / EngineApi / BuiltinReg / TabsApi): MUST keep working byte for byte; (2) installed extensions (zip / crx, files in filesDir/exts/<id>/, id = 32 chars a-p, ExtRegistry.kt, ExtApi.kt for their chrome.* handlers, ExtUpdater.kt, ExtSafety.kt).
 - UI of the extension feature: ExtTray.kt (puzzle tray in 3-dot menu), ExtListScreen.kt (Settings > Extensions, details view with "Dark mode" row), ExtMenus.kt (context menus), ExtDark.kt (per-extension dark mode, pref ext_dark).
