0.0.433 (S8 BUILD: externally_connectable (web page -> extension), commands; S7 + S8 in one patch zip)
- Why: the test extension (ChatGPT Exporter) lists externally_connectable for chatgptexporter.com; a page of that site calls chrome.runtime.sendMessage(extId, ...) and nothing answered. Manifest "commands" were not shown anywhere and chrome.commands.getAll returned [].
- How: new ExtWeb.kt. (a) externally_connectable: for the origins of installed extensions' externally_connectable.matches (patterns checked by ExtSafety.externalPatterns: https / http / * scheme, real host, "*" alone / "<all_urls>" / "*.com" are dropped, max 20) every normal tab gets (1) its own WebMessage listener "MGBExt" limited to those origins by the WebView and (2) a small page script (only on those origins) that gives the page chrome.runtime.sendMessage(extId, msg [, cb]) and chrome.runtime.connect(extId [, {name}]) and NOTHING else (no token, no other chrome.* member). Native side checks the origin the WebView reports (never a value from JS) against the extension's patterns, the extension must be installed and on, else the page gets "Could not establish connection. Receiving end does not exist." (same text for every refusal: nothing leaks). The extension receives runtime.onMessageExternal(message, sender, sendResponse) / runtime.onConnectExternal(port); sender = {origin, url, frameId, tab}. A stopped worker is started first (same path as runtime.sendMessage). Ports: page <-> extension pages, closed when either side leaves (page unload, frame gone, extension page gone); an open port keeps the worker alive. Limits: 1 MB per message (both directions), 60 messages / connects per minute per page, 600 port posts per minute, 20 ports per page, 100 in total. NEVER in private tabs. (b) web_accessible_resources: already implemented in 0.0.108 (EngineHost.extPublic); checked, unchanged. (c) commands: chrome.commands.getAll returns the manifest commands ({name, description, shortcut}) for installed extensions; Settings > Extensions > tap an extension shows a COMMANDS block (description + shortcut text); a tap runs it: _execute_action = open the popup (or action.onClicked), any other command = chrome.commands.onCommand(name, tab) (stopped worker is started first). Android has no keyboard shortcuts here: the shortcut text is information only.
- Shim (chrome-shim.js, additive): deliverMessage / incomingPort take an optional event name; two new lines in onNative for the two external events; one small block at the end (only installed extensions, GAPS): runtime.onMessageExternal / onConnectExternal are announced to Kotlin, so a stopped worker can wake for them. The built-in Media Grabber members are unchanged (node test: not announced, no change).
- Hooks (additive): ChromeBridge.request + TabsApi.fanOut got an optional "event" parameter (default runtime.onMessage); ExtApi: ExtWeb.register() line, 2 port lines (port.post / port.disconnect check ExtWeb first), 1 ctxGone line; ContentInjector.addExtScripts: ExtWeb.attach for non-private tabs.
- Changed files (S7 + S8): app/build.gradle.kts, app/src/main/java/com/jabra/mgb/{ExtManifest.kt (new), ExtWeb.kt (new), ContentInjector.kt, ExtRegistry.kt, ExtApi.kt, ExtSafety.kt, ExtListScreen.kt, ExtTray.kt, ChromeBridge.kt, TabsApi.kt, TabManager.kt, HowToUse.kt}, app/src/main/assets/shim/chrome-shim.js, CHANGELOG_PREPEND_0_0_432.txt, CHANGELOG_PREPEND_0_0_433.txt, HANDOFF_Thazir_EXT_PLAN_0.0.433.txt
- CHANGED BEHAVIOUR: a page of a listed origin now has window.chrome.runtime (sendMessage / connect only), like in Chrome. Extensions without externally_connectable: nothing added anywhere (no listener, no script). Settings > Extensions details shows COMMANDS only when the manifest has commands.
- COULD BREAK: a site that checks window.chrome to detect "Chrome" sees it on the listed origins only. Adding the "MGBExt" listener per tab happens at tab creation and after an extension change (refresh); an already loaded page gets it on its next load. externally_connectable.ids (other EXTENSIONS as senders) is NOT supported (ignored). frameId of a sub frame sender is 1 (not a real frame id). Message from a page to an extension whose worker listens only for onMessage (not onMessageExternal) gets "Receiving end does not exist" like Chrome.
- NOT tested: Gradle build (CI), device. node tests passed: page script (sendMessage promise + callback + lastError, bad id, 1 MB cap, port in / out, pagehide, no chrome on non-http pages) and shim (external events routed to the right listeners, reply, ports, built-in unchanged, onMessage unchanged), glob + pattern helpers. Kotlin only checked for brace / paren balance.
